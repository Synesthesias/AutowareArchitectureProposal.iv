# テストケース仕様書: map_tf_generator

`map_tf_generator` のテストを「単体テスト（gtest）」と「結合テスト（launch_testing / rclcpp）」に分類して定義

## 対象範囲

- テスト対象ノード: `map_tf_generator::MapTfGeneratorNode`
- 実行ファイル: `map_tf_generator`
- 目的: 購読した `sensor_msgs/PointCloud2` の重心を並進とする静的 TF を、`map_frame`（親）から `viewer_frame`（子）へ配信することを確認

## 環境:

- Ubuntu 22.04 + ROS 2 Humble

## 単体テスト（gtest）

前提:
- gtest により C++ レベルでロジックを検証
- 重心計算ロジックを関数としてテスト対象とする
- 例: `std::optional<Eigen::Vector3d> compute_centroid(const sensor_msgs::msg::PointCloud2 &)`

| ID     | 観点                  | 前提           | 入力                                            | 期待結果                                                  | 受入基準                                                      |
| ------ | --------------------- | -------------- | ----------------------------------------------- | --------------------------------------------------------- | ------------------------------------------------------------- |
| UT-001 | 重心計算 正常系       | 関数が利用可能 | 3 点 (1,2,3),(4,5,6),(7,8,9) を持つ PointCloud2 | 重心=(4,5,6)                                              | 3 成分とも許容誤差 ±1e-6 以内                                 |
| UT-002 | 空点群                | 〃             | `width*height=0`                                | 無効（`std::nullopt` / `false` を返す想定）               | 例外を投げず失敗を返す                                        |
| UT-003 | 欠損フィールド        | 〃             | `x,y` のみ等で `z` 欠如                         | 無効（エラー/失敗を返す）                                 | 戻り値で失敗を検出できる                                      |
| UT-004 | 非有限値の扱い        | 〃             | `x/y/z` に NaN/Inf を含む                       | 現在の仕様: 非有限を包含するため結果が NaN/Inf になり得る | 計算結果に NaN/Inf が反映される（将来仕様変更時はテスト更新） |
| UT-005 | 非組織化/組織化の一致 | 〃             | 同一点集合で height=1,width=N と height>1       | 重心は同一                                                | 両ケースの結果が一致                                          |
| UT-006 | 大規模点群の計算量    | 〃             | N≈1e6 の擬似点群                                | 計算が完了する（O(N)）                                    | 実測でタイムアウトしない（CI環境をベンチマーク基準）          |

## 結合テスト（launch_testing / rclcpp）

前提:
- `launch_testing` または rclcpp ベースでノードを実起動し、/tf_static とトピック経由で検証します。
- Publisher 側 QoS はノード期待値（`SensorDataQoS` 等）に合わせます。

| ID     | 機能                  | 前提条件                                                | 入力                                    | 期待される結果                                                      | 受入基準                                          |
| ------ | --------------------- | ------------------------------------------------------- | --------------------------------------- | ------------------------------------------------------------------- | ------------------------------------------------- |
| IT-001 | 重心 TF 配信          | 既定パラメータ（`map_frame=map`,`viewer_frame=viewer`） | 3 点 (1,2,3),(4,5,6),(7,8,9) を publish | 親=`map`, 子=`viewer`, 並進=(4,5,6), 回転=単位, `header.stamp` 伝播 | 2s 以内に TF lookup が成功し並進が ±1e-6 以内     |
| IT-002 | 空点群は無視          | ノード起動済み                                          | `width*height=0` を publish             | 新規 TF は配信されない（ログが出力される場合あり）                  | 既存 TF から変化なし。クラッシュなし              |
| IT-003 | 欠損フィールドは無視  | ノード起動済み                                          | `z` 欠如の PointCloud2                  | TF 未更新＋警告ログ                                                 | `map_frame`→`viewer_frame` の TF が増えない       |
| IT-004 | フレーム ID 反映      | `map_frame:=world`,`viewer_frame:=viz`                  | 単一点 (10,0,0) を publish              | 親=`world`, 子=`viz`, 並進=(10,0,0)                                 | `world`→`viz` の lookup で並進成分が期待値になる  |
| IT-005 | スタンプ伝播          | ノード起動済み                                          | 既知の `header.stamp` を持つ点群        | TF の `header.stamp` が一致                                         | `/tf_static` 受信メッセージの stamp が一致        |
| IT-006 | 再配信と保持          | ノード起動済み                                          | A: 重心 (0,0,0)、続けて B: (1,2,3)      | 保持する TF が最新 B に更新                                         | B 後に新規 `/tf_static` 購読で ~ (1,2,3) を即取得 |
| IT-007 | 非組織化/組織化で一致 | ノード起動済み                                          | 同一点集合で2形態を順に publish         | 生成される並進が一致                                                | 2 回の TF 並進が許容誤差内で一致                  |
| IT-008 | 非有限値の挙動        | ノード起動済み                                          | NaN/Inf を含む点群                      | 並進が NaN/Inf になる可能性を確認                                   | 挙動を記録（将来仕様変更時は XFAIL→PASS へ）      |
| IT-009 | Launch リマップ       | `input_map_points_topic:=/custom/map_cloud` 起動        | `/custom/map_cloud` に publish          | 受信・TF 配信が通常通り                                             | リマップ後も期待 TF が取得可能                    |

## 非機能（参考）

- 性能: 大規模点群でも重心計算は O(N)。CI の制約に合わせてベンチマークは任意実施。
- 耐性: 繰り返し実行や高速 publish、起動時のパラメータ変更があってもクラッシュしない。

## 備考

- QoS は `SensorDataQoS` を前提。Publisher 側の QoS を合わせるか互換設定にすること。
- ノードは `tf2_ros::StaticTransformBroadcaster` により `/tf_static` を配信し、保持されます。新規リスナーは直ちに最新変換を取得できます。
