# pointcloud_preprocessor テスト仕様 (Test Specification)

`pointcloud_preprocessor` パッケージに対する単体テスト (gtest) と結合テスト (ROS 2 launch) の仕様を記述します。README の機能 ID と 1:1 に対応するテストを提供します。

## テストレベルと到達基準

- **単体テスト (gtest)**
  - 対象: ノード内部ロジック（時刻処理、バッファ遷移、フィルタ計算、TF ハンドリング等）。
  - 依存: ROS 通信は最小限にし、必要に応じて TF/Clock をスタブ化（ダミー実装を利用）。
  - 合格基準: すべての機能 ID に対応する期待条件を満たす。
- **結合テスト (ROS 2)**
  - 対象: 実ノードと QoS、TF、タイムアウト、ログ出力を含む振る舞い。
  - 依存: `launch_testing_ros` もしくは専用 Publisher/Subscriber ノードで再現。
  - 合格基準: 期待されるトピック内容・フレーム・ログが観測でき、エラーなく停止する。

## 単体テスト (gtest)

実装指針: `ament_add_gtest` でテストしやすいようロジックを小さな関数へ分離、もしくはフィクスチャを用いてプライベートメンバへアクセスします。数値比較には許容誤差 (1e-6 程度) を設け、TF 変換はモックを返して検証します。

## 実装メモ

- 単体テストは `ament_add_gtest()` を用い、必要なら `include/pointcloud_preprocessor` 配下にテスト専用ヘッダを追加して内部関数へアクセスします。
- 結合テストは `launch_testing_ros` と補助ノード（PointCloud/Twist publisher、TF broadcaster）で構成し、`pytest` から自動実行します。
- 再現性確保のため、固定点群 (pcl::PointXYZ) と deterministic Twist シーケンスをテストデータとして保存します。

到達基準: 単体テストはすべての UT-* が PASS、結合テストは CDN-*/DCMF-* が PASS し、WARN 期待があるケースを除いて追加のエラー/警告を残さないこと。
